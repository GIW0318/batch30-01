# GSB Bugfix Task
## 题面
TLS 1.3 的 0-RTT 通道被反复重放：同一张票据连续提交两次都放行；票据没有和会话绑定；签发时间与过期窗口不比较；最大早期数据量不检查；未知 key_id 的票据也收；未来才生效的票据能过；并发提交时两边都成功；票据缺字段直接抛未处理异常；消费后不记录；不同 guard 实例的票据能互用；大小传负数绕过上限。tls_early_data.py 的 15 条测试现在全挂。需要把票据和会话、key_id 绑定，校验时间窗和数据量，做到一次性消费，未知 key 和未来时间拒绝，并发只放一个，畸形票据统一报错。

## 运行方式
```bash
python -m pytest tests -q
```
